# Formnest 대표 사이트와 대표 작품 완성

## 이어갈 목적

사용자가 승인한 기존 4인 팀의 대표 사이트·대표 작품 제작을 이어갑니다. GitHub 연결 검증은 완료됐으며, 이제 실제 제작 결과의 완성도를 높이는 작업입니다. Formnest는 채택된 이름입니다. 이름 채택과 상표·도메인 권리 확보는 구분합니다.

기존 시안은 출발점이지 유지 조건이 아닙니다. 부분 개선이나 전면 재설계 중 목표에 맞는 방법을 팀이 판단합니다. 기술, 표현 방식, 작품의 보강 범위도 자유롭게 선택합니다. 작품 수를 늘리는 것보다 방문자가 제작 역량을 이해하고 핵심 흐름을 직접 체험할 수 있는 결과가 중요합니다. 현재 구현이 로컬 데모라는 이유만으로 서버·결제·인증을 필수 과제로 만들지는 않습니다.

이 추가 브리프는 기존 목표 안의 제작 재개입니다. 원래 `studio-team.md`, GitHub 연결 검증 기록, 기존 공유 자료와 이력을 보존합니다. 상위 목표 자동 생성 엔진이나 성장 시험은 이번 제작의 완료 조건이 아닙니다. 플랫폼 운영자는 팀의 사이트를 대신 제작하지 않습니다.

## 현재 결과를 읽고 시작할 부분

공동 대화와 공유 자료의 최신 버전을 먼저 확인합니다. 현재 홈은 `site/index.html`, 대표 작품은 `site/demo/`, 실행 안내는 `site/README.md`에 있습니다. `qa/browser-review-v1.md`, `qa/browser-v4-retest.md`, `verification/github-20260909/qa-independent-review.md`, `verification/github-20260911/qa-pr1-supplement.md`와 개발 게시 보고서가 기존 검증 근거입니다. 이후 새 버전이나 회신이 있다면 그 결과를 이어받습니다.

검수에서는 임시 브랜드 문구, 메모 확인만 가능한 문의 영역, 과거의 브라우저 미검증·테스트 수 안내가 남아 있었습니다. 작품 소개도 콘셉트 설명에 비해 실제로 만든 화면과 해결 과정이 충분히 드러나는지 다시 살필 만합니다. 기존 예약 흐름의 실제 Chromium 검증과 줄바꿈 수정은 보존하고, 변경한 동작과 아직 확인하지 않은 경계를 중심으로 검증합니다. 홈 폼의 JavaScript 비활성·실행 실패 시 제출 동작은 소스에서 발견한 확인 후보이며 실제 재현된 결함으로 취급하지 않습니다.

## 동료 협력

첫 작업은 디자인·콘텐츠 동료에게 전달합니다. 디자인이 다른 동료의 상위 책임자가 되는 것은 아닙니다. 브랜드·리서치, 디자인·콘텐츠, 개발, 품질 검증이 필요한 의견과 작업을 서로 요청하고, 기존 공동 작업판의 과제를 확인해 중복 없이 이어갑니다. 이 목표에 필요한 세부 과제는 같은 프로젝트·팀 안에서 생성하고 자청할 수 있습니다. 분담 순서나 산출물 형식을 고정하지 않습니다.

현재 목적에서 무엇을 바꿀지 판단한 뒤 실제 화면과 작품에 반영합니다. 사용자에게 중간 결과와 중요한 판단을 같은 공동 대화로 공유합니다. 독립 QA가 결함을 발견하면 제작 동료가 수정하고 영향 구간을 다시 확인합니다. 필요한 기능이 실제 도구에 없다면 해당 장애를 공유하되, 가능한 내부 제작까지 함께 중단하지 않습니다.

## 기존 PR에서 계속하기

대상은 비공개 저장소 `formnest-studio/studio-site`(ID `1362601656`)의 기존 PR #1입니다. 현재 PR·head/base와 파일을 읽고 확인한 SHA를 기준으로 작업합니다. 과거 보고서의 SHA를 현재 HEAD로 가정하지 않습니다. 최신 공유 산출물과 원격 파일의 차이를 확인하고 어느 버전을 반영했는지 남깁니다.

기존 PR 수정에는 제공된 `github_revise`를 사용합니다. 입력은 `connectionId`, `number: 1`, `operationId`, 현재 PR의 `expectedHeadSha`, `files`, `message`입니다. 새 수정에는 새 operationId를 사용하며, 응답이 불명확한 재시도는 같은 ID와 같은 입력을 유지합니다. HEAD 충돌은 최신 내용을 다시 읽고 협의할 사안이며 강제 덮어쓰기하지 않습니다. 이 작업을 위해 새 PR을 만들거나 기존 PR을 병합하지 않습니다.

개발·디자인은 기존 쓰기 권한 안에서 협력하고, QA는 읽기 권한으로 실제 PR의 변경 SHA와 공유 파일을 대조합니다. 변경 파일·새 commit SHA·검증 결과를 함께 공유합니다. 운영자가 미리보기에 연결할 수 있도록 최신 `site/` 산출물의 경로·artifact ID·버전을 분명하게 남깁니다. 캡처와 검증 보고서가 어떤 소스 버전인지도 연결합니다.

## 이번 완료 기준

- Formnest의 브랜드와 제작 역량이 대표 사이트에 반영되고, 임시 안내와 최신 상태가 어긋나지 않습니다.
- 대표 작품의 핵심 흐름을 실제로 체험할 수 있으며, 자체 제작 데모와 고객 납품 실적을 혼동시키지 않습니다.
- 실제 PC·모바일 화면, 주요 기능과 키보드 사용, 수정 영향 구간의 검증 근거를 남깁니다. 새로고침·저장 실패·손상 등 남은 실패 경로와 성능 측정도 결과에 맞게 확인하되, 실행하지 않은 검증을 통과로 표현하지 않습니다.
- 최신 실행 방법·알려진 한계·파일 버전·PR SHA와 캡처가 서로 일치합니다. 과거 보고서는 이력으로 보존하고 현재 인도 안내를 갱신합니다.
- 사용자에게 실제 화면과 체험 방법을 제시하고 최종 디자인 확인을 기다립니다. 기술 검사 통과만으로 사용자 최종 승인을 대신하지 않습니다.

## 이번에 포함하지 않는 행동

이메일 주소의 공개 적용, 실제 문의 접수 연동, 고객에게 보내는 메일·메시지·자동 회신, 계약·결제, 공개 배포·병합, 도메인 구매, 계정·저장소 추가 연결은 이번 범위에 포함하지 않습니다. 문의 영역의 내부 화면과 문구 제안은 제작할 수 있으며, 실제 연락 경로가 연결된 것처럼 표시하지 않습니다.

기존 팀 구성, 모델, CPU·메모리·디스크·모델 사용량 상한과 자동 탐색 설정은 유지합니다. 다른 팀·프로젝트·저장소로 권한을 넓히지 않습니다. 인증정보는 플랫폼이 관리하며 키·토큰·복구코드를 결과물이나 대화에 담지 않습니다.

## 운영자 실행

`npx tsx scripts/continue-studio-refinement.ts`는 기본적으로 GET 점검과 로컬 준비 기록만 수행합니다. `--inspect`는 준비 기록도 쓰지 않습니다. `--start`만 기존 공동 대화의 디자인 동료에게 task 한 건을 전달합니다. 준비 기록은 `.verification/studio-refinement-20260911/continuation.json`입니다. 원래 launch·브리프 해시, 추가 브리프, 현재 4인 구성·저장소 권한·연결 세대와 최신 공유자료를 확인합니다. 같은 전달의 불명확한 응답은 대화의 동일 키를 먼저 확인하며 새 메시지로 자동 재전송하지 않습니다.
